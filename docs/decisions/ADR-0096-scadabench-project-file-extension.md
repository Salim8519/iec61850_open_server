# ADR-0096: Project files use the .scadabench extension

Accepted: 2026-10-21. Owner: project files change from `.subsim` to `.scadabench`; no buyers exist
yet, so there is no compatibility promise for old files. Choices the owner made are marked (owner).

## Decision

- **User-facing project files are `.scadabench` (owner).** The download is
  `substation.scadabench`, the file chooser offers `.scadabench`, Settings names the format
  "ScadaBench project (.scadabench)". The archive itself is unchanged: the same ZIP with one
  `project.json`, format 15, so a project written before this change opens once its file is
  renamed by hand.
- **`.subsim` is not opened (owner).** A picked file whose name ends in `.subsim` (any letter
  case) is refused before anything is sent, with "This is an old project file (.subsim).
  ScadaBench now uses .scadabench project files." The engine refuses it too: `POST /project/open`
  answers 400 with code `old_project_file` and that text, in both engines, before it restores anything. The file chooser lists `.subsim` only so that picking one explains itself.
- **The app's own copies use the new extension.** `autosave.scadabench` and
  `recovery/before-*-<uuid>.scadabench` / `unreadable-autosave-<uuid>.scadabench`. The
  `autosave.tmp` and `autosave.journal` names do not carry the extension and stay.
- **Existing app-owned data keeps working.** At startup, with the data folder owned and before the
  autosave journal is folded or anything is read, both engines rename the app's own
  `autosave.subsim` and `recovery/*.subsim` in place (`studio_app.projects.extension_migration`,
  `engine/internal/store/projectfile`; `studio_server --fold-journal` does it too, so the
  development launcher's hand-over from Go to Python sees the same names). Nothing is deleted or
  overwritten: when the new name already exists both files stay and the new one is used; a folder
  or link with the old name is left alone. A rename the system refuses (a program holds the file
  open) stops startup for the autosave, with a plain message and the file untouched, and is only
  journaled for a recovery copy. Every outcome is one line in the append-only
  `logs/project-file-migrations.jsonl` (`kind`, `at`, `correlation_id`, `from`, `to`, and `reason`
  or `error`); one `correlation_id` ties the lines of one start.
- **Windows file association: none existed.** The installer registered no ProgID or extension, and
  the launcher takes no file argument, so nothing was changed there. Associating `.scadabench`
  with double-click opening needs a launcher argument first and is a separate decision.

## Compatibility

- Python (frozen, owner approved) and Go change together and stay byte-identical: the refusal body
  is part of `http_golden.json` (regenerated by `http_gen.py`), the rename and its journal are
  cross-checked against Python by `projectfile/python_test.go` on five folder shapes.
- Supersedes the sentence in ADR-0047 that `.subsim` stays an internal identifier. Older
  inventories and change records under `docs/architecture/go-engine/` and `docs/changes/` name
  `.subsim`; they describe what was true when written and are not rewritten.
- A developer who runs an older build after a newer one writes a fresh `autosave.subsim` next to
  the migrated file; the next start keeps both and opens the `.scadabench` file (journaled).
