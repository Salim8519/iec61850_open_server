# ADR-0105: Gateway "Add points": from an IED, made up, pasted or from an Excel template

Accepted: 2026-10-22. Owner request: rebuild the gateway simulator's "Add points" experience (one dialog, from an
IED or simulated, a type list per protocol, paste from Excel, an Excel template with drop-downs, a smart Propose
that adds only new points). Change [0168](../changes/2026/0168-gateway-add-points.md). Builds on
[ADR-0091](ADR-0091-gateway-own-points.md) (own points), [ADR-0095](ADR-0095-universal-point-kinds.md) (one kind
badge) and [ADR-0101](ADR-0101-save-always.md) (save always, Undo for whole-list actions).

## Problem

Points could only be proposed (all IEDs, replacing the IED points), made up one at a time, or imported as CSV.
A SCADA engineer who wants three breakers of one bay, or who has the SCADA point list in Excel, had to edit
addresses by hand, and Propose threw away renamed points and edited addresses.

## Decision

1. **One planner in Go** (`studio/engine/internal/gateway/addpoints`, pure, no HTTP): it plans and checks; the
   list only changes when the page saves it with `PUT /tools/gateway/points`, which checks it again with the
   unchanged `gateway.ValidatePoints`.
2. **One type catalog** (`addpoints/catalog.go`): per protocol, each existing gateway kind with a plain name, the
   protocol's type ids (IEC 104 `M_SP 1/30` …, DNP3 `g1v2 / g2v2` …, Modbus `FC2` …, taken from the native worker)
   and "most used". The page draws it with one `TypeList` component in every protocol ("Most used", "More types").
   A new kind is one line per protocol here (and in `gateway.Kinds`); no frontend list of types exists.
3. **From an IED**: the engine lists only the signals of that IED that fit the type (ST/MX values whose IEC 61850
   type the kind carries, `gateway.AllowedKinds`; commands by data class, DPC → double command, others → single),
   names them from the SCL description and gives the next free addresses. A command point is an IED point
   (`ied` + `ref` of the controllable object), so a SCADA command on it goes through the existing
   `service/commands.go` path to that IED at once. "Also add its status point" (ticked by default) adds the
   control's status and **pairs the addresses**: both at the same distance from the start of their blocks
   (IEC 104 double point 20003 ↔ double command 50003; Modbus discrete input 5 ↔ coil 5; DNP3 index n ↔ CROB n),
   or the next free address when that is used. A real IED shows "This is a real device. SCADA commands will
   operate it." and needs "I understand" before Add.
4. **Simulated**: ADR-0091 own points unchanged, plus "Add a range": N points of one type at consecutive
   addresses from X; a used address stops the plan with a problem (nothing moves silently).
5. **Paste from Excel / Excel template**: pasted rows (tabs, or `;`/`,`) or an uploaded `.xlsx` are read into
   rows; a title row is recognised by its words (address/IOA/index, type, IED, point/reference/path/signal,
   name/description, scale), without one each column is guessed from its first row. Every row is checked (type
   of this protocol, project IED or "Simulated", a fitting signal, free address, scale); bad rows carry a reason
   and nothing is added until all are right. The template (`GET /tools/gateway/points.xlsx`) is generated by the
   engine: a Points sheet with drop-down validations for Type (the catalog), IED (project IEDs + "Simulated (made
   up)") and Point (`INDIRECT` of a named range `P_<ied>_<type>` on a hidden Lists sheet that holds only that
   IED's fitting references), a whole-number rule for Address and a How to fill sheet. Upload adds rows (it never
   replaces the list). CSV import/export is unchanged.
6. **Smart Propose**: `POST /tools/gateway/propose` with the Go-only `mode` (`replace` | `add_new`), `current`
   (the page's list) and optional `ieds` (ticked IED ids) runs the same selection as Propose for the ticked IEDs,
   fills names from the SCL, adds every command's status point, pairs command addresses and answers `summary`
   (one row per IED: offered, new, ticked) for the preview. `add_new` keeps every point of `current` exactly as
   it is and adds only missing points at free addresses; `replace` re-proposes and keeps own points. Without
   `mode` the route answers byte-identically to before (Python parity).

### Routes (Go only; added to `toolsapi.OwnPointRoutes`)

| Route | Body / query | Answer |
| --- | --- | --- |
| `GET /tools/gateway/types` | `protocol` | `{types: [{kind, name, type_id, most_used}]}` |
| `POST /tools/gateway/candidates` | `{protocol, ied, kind, q, points}` | `{items: [{ref, name, description, value_kind, fc, cdc?, status_ref?, taken, suggested}], total, ied: {id, name, role}}` (max 300 items) |
| `POST /tools/gateway/points/from-ied` | `{protocol, ied, kind, picks: [{ref, name?, address?}], with_status, points}` | plan + `ied` |
| `POST /tools/gateway/points/rows` | `{protocol, text, points}` | plan + `columns` |
| `GET /tools/gateway/points.xlsx` | `protocol` | the template (`.xlsx` download) |
| `POST /tools/gateway/points.xlsx` | `{protocol, data: base64, points}` | plan + `columns` |
| `POST /tools/gateway/points/new` | adds optional `count`, `from`, `name` | plan (without `count`: unchanged ADR-0091 answer) |
| `POST /tools/gateway/propose` | adds optional `mode`, `current`, `ieds` | `{points, notes, summary}` (without `mode`: unchanged) |

A plan is `{rows: [{number, point, problem, status_for?, cells?}], points, ok}`; `points` holds the new points
only when `ok` (every row can be added).

## Dependency

`github.com/xuri/excelize/v2` **v2.9.1** (BSD-3-Clause, pure Go) to write and read `.xlsx`, with its imports
`xuri/efp` v0.0.1, `xuri/nfp` v0.0.1 (BSD-3-Clause), `richardlehane/mscfb` v1.0.4 and `msoleps` v1.0.4
(Apache-2.0), `tiendc/go-deepcopy` v1.6.0 (MIT), `golang.org/x/crypto` v0.38.0, `x/net` v0.40.0 and `x/text`
v0.25.0 (BSD-3-Clause). Pinned in `studio/engine/go.mod`/`go.sum`; licence files in
`studio/packaging/third_party/go-licenses/` (index in its README), shipped by the Go release to
`_internal/licenses/go-*`. Chosen because it is the widely used pure-Go xlsx library (no CGO, works with
`CGO_ENABLED=0`) and supports data validation and defined names, which the template needs.

## Compatibility

No project data format change: planned points are ordinary gateway points (IED points or ADR-0091 own points).
Requests without the new fields are answered as before; the Python-parity route test still passes. The frozen
Python engine answers the new routes 404 and ignores `mode`/`count`, so Add points shows the engine's error there
and Propose falls back to the old proposal (Go is the default engine). The old "Add point" form lives on as
Simulated › One point.
